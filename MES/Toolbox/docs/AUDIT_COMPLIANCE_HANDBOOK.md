## 🏭 1. มาตรฐาน IATF 16949:2016 (ระบบบริหารคุณภาพอุตสาหกรรมยานยนต์)

### 1.1 Clause 8.5.2: การชี้บ่งและการสอบกลับได้ (Identification and Traceability)
* **การควบคุมสูตรโครงสร้างการผลิต (BOM & ECN Traceability):**
  * ทุกการแก้ไขส่วนประกอบสูตร (Component SAP No, อัตราส่วนการใช้ Quantity, หรือต้นทุนวัสดุ) ระบบจะบังคับบันทึกประวัติการเปลี่ยนแปลงลงใน `dbo.SYSTEM_LOGS`
  * บันทึก JSON Snapshot ข้อมูลก่อนแก้ไข (`old_value`) และข้อมูลหลังแก้ไข (`new_value`) ควบคู่กับรหัสพนักงาน วัน-เวลา และ IP Address
  * หน้าจอ `BomManagerTab.jsx` มีปุ่ม **Audit History (Diff Viewer)** แสดงการเปรียบเทียบจุดแตกต่างแบบ Before (สีแดง) / After (สีเขียว) ให้เห็นทันที
* **การตรวจสอบคุณภาพในกระบวนการพ่นสี (Paint Chemical Inspection):**
  * ข้อมูลการตรวจสอบสารเคมีในสายการผลิตพ่นสีถูกควบคุมผ่าน `dbo.PAINT_CHEM_HEADER` และ `dbo.PAINT_CHEM_ITEMS`
  * กระบวนการอนุมัติแบบ 4 ระดับ (Operator -> Leader -> QA -> Chemist) มีการบันทึก Audit Log ชัดเจนทุกขั้นตอน (`SUBMIT_SHEET`, `APPROVE_SHEET`, `UNLOCK_SHEET`) ป้องกันการปลอมแปลงผลตรวจเช็คย้อนหลัง

### 1.2 Clause 7.5.3: การควบคุมข้อมูลเอกสาร (Control of Documented Information)
* **การป้องกันการแก้ไขโดยไม่ได้รับอนุญาต (Anti-Tampering):**
  * ตาราง `dbo.SYSTEM_LOGS` ได้รับการออกแบบให้เป็น **Append-Only** (มีเฉพาะคำสั่ง `INSERT`) ไม่มี Endpoint หรือสิทธิ์ในหน้าบ้านที่อนุญาตให้ `UPDATE` หรือ `DELETE` ประวัติการกระทำใดๆ ทั้งสิ้น
  * เอกสารและใบงานมีเลขที่อ้างอิงกำกับชัดเจน (`ref_id`) เชื่อมโยงกับฐานข้อมูล ERP (SAP)

## 🔒 2. มาตรฐาน ISO/IEC 27001:2022 (ระบบบริหารความมั่นคงปลอดภัยสารสนเทศ)

### 2.1 Control A.8.12: การป้องกันข้อมูลรั่วไหล (Data Leakage Prevention - DLP)
* **Dynamic Vector Security Watermark (ลายน้ำโปร่งแสงตรวจจับการถ่ายภาพ):**
  * บนหน้าจอที่มีข้อมูลความลับทางธุรกิจขั้นสูง (เช่น สูตร BOM, ต้นทุนสินค้า SAP Valuation, และตาราง Audit Logs) ระบบจะฉาบลายน้ำแบบ Dynamic เวกเตอร์โปร่งแสง (Opacity ~4%) ทับทั่วทั้งตาราง
  * **เนื้อหาลายน้ำระบุตัวตนสด:** `ชื่อ-นามสกุลพนักงาน [รหัสพนักงาน] • วันที่เข้าดู • ชั้นความลับ (SNC CONFIDENTIAL)`
  * **ผลลัพธ์ในการยับยั้ง:** หากมีพนักงานหรือบุคคลภายนอกใช้สมาร์ตโฟนแอบถ่ายรูปหน้าจอ หรือบันทึกภาพหน้าจอออกไป ลายน้ำจะปรากฏบนรูปภาพอย่างชัดเจน ทำให้ระบุตัวผู้กระทำความผิดและเวลาเกิดเหตุได้ทันที 100%
  * **ความลื่นไหลของระบบ (Zero UX Interference):** ใช้เทคโนโลยี CSS `pointer-events: none` และ `user-select: none` ทำให้ลายน้ำไม่ขัดขวางการคลิก การเลื่อนหน้าจอ หรือการทำงานตามปกติแม้แต่น้อย

### 2.2 Control A.8.15 & A.8.16: การบันทึกและติดตามประวัติเหตุการณ์ (Logging & Monitoring)
* **ระบบตรวจจับหมายเลข IP แท้จริง (True Client IP Detection):**
  * ป้องกันการปลอมแปลง IP (Anti-IP Spoofing) โดยไล่ตรวจเช็ค Headers เรียงลำดับจาก `HTTP_CF_CONNECTING_IP` -> `HTTP_X_FORWARDED_FOR` -> `HTTP_X_REAL_IP` -> `REMOTE_ADDR`
  * สามารถแยกแยะอุปกรณ์ที่เข้าใช้งานจากเครือข่ายภายในโรงงาน (Private IP เช่น `10.1.x.x`) หรืออินเทอร์เน็ตภายนอกผ่านเครือข่ายมือถือ (Public IP เช่น `49.229.x.x`) ได้อย่างแม่นยำ
* **โครงสร้างประวัติการใช้งานแบบครบถ้วน (5W1H):**
  * **Who:** `username`, `user_id`, `role`, `fullname`
  * **What:** `action` (เช่น `CREATE_USER`, `UPDATE_BOM_COMPONENT`, `SYNC_SAP_COST`)
  * **Where:** `module`, `ip_address`, `user_agent` (เบราว์เซอร์และระบบปฏิบัติการ)
  * **When:** `created_at` (เวลามาตรฐานระดับวินาที)
  * **Target:** `ref_id` (Primary Key หรือรหัสสินค้าเป้าหมาย)
  * **Evidence:** `old_value` และ `new_value` ในรูปแบบ JSON Snapshot

### 2.3 Control A.5.15 & A.8.2: การควบคุมการเข้าถึงและสิทธิ์ผู้ใช้งาน (Access Control & Session Security)
* **การจัดการสิทธิ์ตามบทบาท (Role-Based Access Control - RBAC):**
  * สิทธิ์การเข้าถึงหน้าจอและปุ่มกดถูกควบคุมแบบ Granular Permissions ผ่านตาราง `dbo.PERMISSIONS` และ `dbo.ROLE_PERMISSIONS`
* **การตัดเซสชันเมื่อไม่มีการใช้งาน (Inactivity Auto-Logout):**
  * เมื่อไม่มีการขยับเมาส์หรือกดแป้นพิมพ์เกิน 60 นาที ระบบจะแสดง Modal นับถอยหลังเตือน 30 วินาที หากไม่มีการตอบรับ ระบบจะทำการ Logout และทำลาย Session ทันที
* **การตัดเซสชันข้ามแท็บพร้อมกัน (Cross-Tab Synchronization):**
  * ใช้เทคโนโลยี `BroadcastChannel` (`mes_auth_channel`) เพื่อให้การ Logout ในแท็บใดแท็บหนึ่ง ปิดเซสชันในทุกแท็บของเบราว์เซอร์พร้อมกันทันที ป้องกันเซสชันค้างบนเครื่องพนักงาน

### 2.4 Control A.8.24: การใช้การเข้ารหัสลับ (Cryptography & Transport Security)
* **การจัดเก็บรหัสผ่าน:** เข้ารหัสผ่านด้วยอัลกอริทึม **BCrypt** พร้อมการ Salt ระดับความปลอดภัยสูง ไม่มีการจัดเก็บรหัสผ่านเป็น Plaintext เด็ดขาด
* **การเข้ารหัสข้อมูลขณะส่งผ่านเครือข่าย:** บังคับใช้งานโปรโตคอล **HTTPS (TLS 1.2/1.3)** ตลอดเส้นทาง
* **การป้องกันการโจมตีข้ามไซต์ (CSRF Protection):** ทุกคำสั่งแก้ไขข้อมูล (`POST`, `PUT`, `DELETE`) ต้องมีและตรวจสอบ `X-CSRF-TOKEN` จาก Session

## 🛡️ 3. พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (Thailand PDPA)

### 3.1 มาตรา 37: มาตรการรักษาความมั่นคงปลอดภัยของข้อมูลส่วนบุคคล
* **นโยบายห้ามบันทึกข้อมูลส่วนบุคคลลงใน LocalStorage (BYOD Zero-Data-Leakage Policy):**
  * เนื่องจากพนักงานในโรงงานเข้าถึงระบบผ่านโทรศัพท์มือถือส่วนตัว (BYOD) ระบบจึงมีนโยบายเข้มงวด: **ห้ามจัดเก็บข้อมูลส่วนบุคคล (PII), เงินเดือน, หรือข้อมูลพนักงานใน `localStorage` หรือ `sessionStorage` บนเครื่องผู้ใช้**
  * ข้อมูลจะคงอยู่เฉพาะในหน่วยความจำ RAM ของ React State เท่านั้น และจะถูกล้างทิ้งทันทีเมื่อปิดแท็บหรือ Logout ทำให้เมื่อโทรศัพท์สูญหายหรือพนักงานลาออก จะไม่มีข้อมูลค้างอยู่บนเครื่อง

### 3.2 มาตรา 39: บันทึกรายการกิจกรรมการประมวลผล (Record of Processing Activities - ROPA)
* ทุกกิจกรรมที่มีการเพิ่ม แก้ไข หรือระงับบัญชีพนักงาน (`CREATE_USER`, `UPDATE_USER`, `TOGGLE_STATUS`, `RESET_PASSWORD`) จะถูกบันทึกลงใน Audit Logs พร้อมระบุตัวตนของผู้ดูแลระบบที่สั่งการ ทำให้สามารถตรวจสอบย้อนหลังได้ตลอดเวลาตามที่กฎหมายกำหนด

## 💬 4. คู่มือแนวทางการตอบข้อซักถามออดิท (Auditor Q&A Cheat Sheet)

เมื่อผู้ตรวจประเมินตั้งคำถาม สามารถเปิดหน้าจอระบบควบคู่กับการตอบตามแนวทางมาตรฐานนี้ได้ทันที:

### คำถามที่ 1: "ระบบมีวิธีควบคุมความถูกต้องและการตรวจสอบย้อนกลับของสูตรการผลิต (BOM) อย่างไร?"
> **แนวทางการตอบ:**  
> "ระบบ MES ควบคุมสูตรการผลิตผ่านระบบ Versioning และ ECN ครับ ทุกครั้งที่มีการแก้ไขส่วนประกอบหรือสัดส่วนวัตถุดิบ ระบบจะสร้าง JSON Snapshot ของข้อมูลเดิม (Before) และข้อมูลใหม่ (After) เก็บไว้ในตาราง Audit Log ส่วนกลางโดยอัตโนมัติ  
> ผู้ตรวจสามารถดูได้ที่หน้า **System Settings -> BOM Manager** และคลิกปุ่ม **ประวัติการแก้ไข** ระบบจะแสดงตาราง Diff เปรียบเทียบข้อมูลที่เปลี่ยนไปชัดเจนว่า ใครเป็นคนแก้ จาก IP ไหน และเปลี่ยนจากค่าเดิมเท่าไรเป็นเท่าไรครับ"

---

### คำถามที่ 2: "ข้อมูลความลับทางธุรกิจ เช่น สูตรการผลิต หรือต้นทุนสินค้า มีมาตรการป้องกันการรั่วไหลผ่านการถ่ายภาพหน้าจออย่างไร?"
> **แนวทางการตอบ:**  
> "ระบบได้ติดตั้งมาตรการป้องกันการรั่วไหล (Data Leakage Prevention - DLP) ตามมาตรฐาน ISO/IEC 27001 Control A.8.12 ด้วยระบบ **Dynamic Vector Security Watermark** ครับ  
> บนหน้าจอที่มีข้อมูลอ่อนไหว เช่น BOM และ SAP Valuation จะมีลายน้ำโปร่งแสงแบบ Dynamic ฉาบอยู่ทั่วตาราง โดยดึงชื่อ-นามสกุล, รหัสพนักงานของผู้ที่กำลังเปิดดู, พร้อมวันที่และระดับชั้นความลับมาแสดงผลตลอดเวลา หากมีผู้ไม่หวังดีใช้มือถือถ่ายรูปหน้าจอ ลายน้ำนี้จะติดไปกับภาพถ่ายทันที ทำให้บริษัทสามารถสืบสวนและระบุตัวผู้ทำภาพหลุดได้อย่างชัดเจนครับ"

---

### คำถามที่ 3: "หากมีผู้กระทำความผิดในระบบ แล้วอ้างว่าตนเองไม่ได้ทำ หรือมีคนอื่นสวมรอย ระบบมีหลักฐานปฏิเสธไม่ได้ (Non-Repudiation) อย่างไร?"
> **แนวทางการตอบ:**  
> "ระบบมีหลักฐานประกอบครบถ้วนตามหลัก 5W1H ในตาราง Audit Logs ครับ โดยบันทึก:  
> 1) รหัสบัญชีผู้ใช้งานที่ยืนยันตัวตนผ่าน BCrypt Password  
> 2) หมายเลข True Client IP โดยตรวจจับผ่าน Proxy Header เพื่อป้องกันการปลอม IP  
> 3) User Agent ระบุรุ่นอุปกรณ์และเบราว์เซอร์  
> 4) วัน-เวลาที่ระดับวินาที  
> 5) ข้อมูลเดิมเทียบกับข้อมูลใหม่ และระบบมี Session Inactivity Timeout ตัดการเชื่อมต่ออัตโนมัติหากไม่มีการใช้งาน ทำให้ไม่สามารถอ้างการเปิดเครื่องทิ้งไว้ได้ครับ"

---

### คำถามที่ 4: "ระบบมีการป้องกันการโจมตีทางเว็บอย่างไร เช่น SQL Injection และ CSRF?"
> **แนวทางการตอบ:**  
> "ฝั่ง Backend API ใน PHP ใช้ **PDO Prepared Statements** แบบพารามิเตอร์ 100% ทุก Query ไม่มีการนำสตริงจากผู้ใช้มาต่อเป็นคำสั่ง SQL จึงป้องกัน SQL Injection ได้อย่างเด็ดขาด  
> ส่วนการเปลี่ยนแปลงสถานะข้อมูลทุกคำสั่ง (`POST`, `PUT`, `DELETE`) มีการตรวจสอบความถูกต้องของ `X-CSRF-TOKEN` ที่ผูกกับเซสชันทุกครั้ง เพื่อป้องกันการโจมตีแบบ Cross-Site Request Forgery ครับ"

---

### คำถามที่ 5: "พนักงานใช้งานระบบผ่านโทรศัพท์มือถือส่วนตัว (BYOD) มีความเสี่ยงที่ข้อมูลของบริษัทจะตกค้างในเครื่องพนักงานหรือไม่?"
> **แนวทางการตอบ:**  
> "ไม่มีครับ สถาปัตยกรรมของระบบมีนโยบาย **Zero Sensitive Client Storage** อย่างเคร่งครัด ข้อมูลทางธุรกิจ ข้อมูลสต็อก และข้อมูลพนักงานทั้งหมดจะถูกเก็บเฉพาะในหน่วยความจำชั่วคราว (React State) เท่านั้น จะไม่มีการเขียนลงใน LocalStorage หรือแคชถาวรบนอุปกรณ์ และเมื่อพนักงานปิดเบราว์เซอร์หรือกด Logout ระบบจะสั่ง Clear ข้อมูลที่เกี่ยวข้องทั้งหมดทันทีครับ"

---

### คำถามที่ 6: "ในกรณีที่ต้องการสอบสวนเหตุการณ์ย้อนหลัง สามารถเรียกดูประวัติได้อย่างไร?"
> **แนวทางการตอบ:**  
> "ผู้ดูแลระบบที่มีสิทธิ์สามารถเข้าเมนู **User & Access Management -> Audit Logs** ซึ่งสามารถกรองดูตามช่วงวันที่, ประเภท Action, รหัสโมดูล, หรือค้นหาด้วย Keyword เช่น หมายเลข IP หรือชื่อพนักงานได้ทันที และมีปุ่มคลิกดู JSON Data ก่อนหน้าและหลังการเปลี่ยนแปลงอย่างโปร่งใสครับ"
