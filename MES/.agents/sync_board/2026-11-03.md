     - **หน้า Home**: API `dailyLogManage.php?action=get_initial_data` ถูกยัดเยียดคิวรีสรุปกะ Morning Brief (`fn_GetManpowerSummary_V2`, สแกน Stock Transactions, รวมค่าไฟ/แก๊ส) ทำงานทุกครั้งที่เข้าหน้า Home แม้ยังไม่ได้กดเปิด Modal (กินเวลา 4 วินาทีเต็ม)
     - **หน้า System Settings (Item Master)**: `ItemMasterTab.jsx` ยิง `limit: 2000` ดึงข้อมูลทั้งหมด 1,918 รายการทุกครั้ง และฝั่ง SQL Server ใช้ CTE ที่รัน Correlated Subquery `STUFF(... FOR XML PATH)` รวมโมเดลและช่วงสปีดทุกแถวก่อนแบ่งหน้า (กินเวลา 6.2 วินาที)
     - **หน้า Team Planner**: มีงานสะสม 4,684 รายการ แต่ไม่มีดัชนี (Non-clustered Index) บน `Visibility` และ `CreatedAt` ทำให้เกิด Full Table Scan + Disk Sort ทุก 30 วินาทีจากการ Polling ในพื้นหลัง แถมยัง Polling ซ้ำข้อมูล Master Data (โครงการ, สเปซ, รายชื่อผู้ใช้) ทั้งที่ไม่ได้เปลี่ยนแปลง
     - **ขนาด Bundle บนเบราว์เซอร์**: ไฟล์เครื่องยนต์หลักรวมไลบรารีขนาดใหญ่ (`xlsx`, `jspdf`) ไว้ด้วยกัน ทำให้เบราว์เซอร์ต้องดาวน์โหลดและประมวลผลนาน
- **สิ่งที่แก้ไขไป (What)**:
  1. **Decouple Morning Brief from Home Page (`dailyLogManage.php`, `MorningBriefModal.jsx`)**:
     - แยกฟังก์ชันสรุปกะ Morning Brief ออกมาเป็น `case 'get_morning_brief'` แบบ On-demand
     - หน้า Home โหลดเฉพาะกะผู้ใช้และวันที่ยังไม่ได้อ่าน ลดเวลาโหลดหน้าแรกจาก 4,000ms เหลือ < 50ms
  2. **Two-Stage CTE Pagination & Sub-types Optimization (`itemMasterManage.php`, `ItemMasterTab.jsx`, `systemSettingsApi.js`)**:
     - ปรับ SQL Query ใน `itemMasterManage.php` ให้ใช้ Two-Stage CTE: สเตจแรกคัดกรองและแบ่งหน้าเฉพาะ `item_id` ให้เหลือ 25-50 แถว แล้วค่อย `JOIN` กลับมารัน `STUFF(... FOR XML PATH)` บน 25-50 แถวเป้าหมาย (ลดเวลาจาก 6,200ms เหลือ < 300ms)
     - เพิ่ม Endpoint `get_sub_types` ดึงกลุ่มย่อยวัสดุอย่างรวดเร็ว (2ms)
     - ปรับ `ItemMasterTab.jsx` ให้แบ่งหน้าฝั่งเซิร์ฟเวอร์ (Server-side Pagination ครั้งละ 25-50 รายการ) และดึงข้อมูลเต็มเมื่อกด "Export Excel" เท่านั้น
  3. **Team Planner Indexing & Selective Polling (`tasks.php`, `TeamPlannerApp.jsx`, `db_changes.md`)**:
     - สร้างดัชนี `IX_TeamPlanner_Tasks_Vis_Created` บน `dbo.TeamPlanner_Tasks (Visibility, CreatedAt DESC)` ขจัดปัญหา Full Table Scan
     - ปรับการ Polling พื้นหลัง (ทุก 30 วินาที) ให้ดึงเฉพาะข้อมูลที่มีการเคลื่อนไหวจริง (`tasks`, `events`, `activities`) และไม่ดึงข้อมูล Master ซ้ำซ้อน (`projects`, `spaces`, `users`)
  4. **Vite Vendor Chunk Splitting (`vite.config.js`)**:
     - ตั้งค่า `manualChunks` แยก `vendor-xlsx` (~424kB) และ `vendor-pdf` (~660kB) ออกจากไฟล์หลัก
     - ลดขนาด Core Engine (`mes-engine-*.js`) จาก 347 kB เหลือเพียง 111 kB (Gzip ~34 kB)
  5. **Architecture Standards (`ARCHITECTURE.md`)**:
