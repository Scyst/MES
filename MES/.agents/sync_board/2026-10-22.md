### In-process Quality System (IQS) Phase 1: Pull Test & Spot Weld Quality System
- **เวลาทำงาน (Time)**: 08:53 - 09:05 22/10/26
- **ปัญหา / สิ่งที่ต้องทำ (Why)**:
  - ผู้บริหารต้องการเปลี่ยนระบบการบันทึกผลการทดสอบแรงดึง (Pull Test), เช็คเคาะ, เช็คระยะ และพารามิเตอร์ตู้คอนโทรลเครื่องจักร Spot Welding จากเดิมที่ส่งใน Line / เขียนใบกระดาษ มาเป็นระบบดิจิทัลบน MES เพื่อเป็นหลักฐาน Audit-ready ที่ตรวจสอบย้อนหลังได้จริง มีความสมบูรณ์ตามมาตรฐานสากล
- **สิ่งที่แก้ไขไป (What)**:
  1. วิเคราะห์เอกสาร "การทดสอบแรงดึง" และภาพถ่ายจริง วางแผนสถาปัตยกรรมระบบ IQS ทั้ง Phase 1 และ Phase 2 ใน `iqs_system_plan.md`
  2. สร้างตารางและ Index ในฐานข้อมูล SQL Server 2016 ครบ 5 ตาราง:
     - `IQS_ROUND_TEMPLATES`: แม่แบบช่วงเวลาทดสอบมาตรฐาน (08:30, 10:30, 13:00, 15:30, 20:30, 22:30, 02:30)
     - `IQS_ROUNDS`: หัวรอบการทดสอบ รองรับผู้ทดสอบหลัก + ผู้ร่วมทดสอบสูงสุด 2 คนจากตาราง `USERS`
     - `IQS_TEST_RECORDS`: บันทึกผลทดสอบรายเครื่อง เชื่อมกับ `PE_MACHINES` โดยตรง ผล OK/NG, ตัวเลขเช็คเคาะ, เช็คระยะ, เวลา Stamp Server
     - `IQS_ATTACHMENTS`: จัดเก็บรูปตอนเทสดึง + รูปหน้าตู้คอนโทรล พร้อม SHA-256 Hash ตรวจสอบความถูกต้อง
     - `IQS_AUDIT_LOGS`: บันทึก Audit Trail ทุกการสร้าง ปิดรอบ และอนุมัติ NG
  3. พัฒนา Backend API `page/IQS/api/iqs_api.php` พร้อม CSRF, Input Validation, Transaction Rollback, และ API Response Contract
  4. พัฒนา Web UI และ Client Script `page/IQS/iqsUI.php`, `page/IQS/css/iqs.css`, `page/IQS/script/iqs.js` แบบ Mobile-first (ปุ่มสัมผัส ≥ 44px), ตรวจสอบสถานะ Online/Offline, แนบรูปจากกล้องสด (`capture="environment"`), และแถบความคืบหน้าการตรวจรอบ
  5. พัฒนารายงานการพิมพ์ / PDF `page/IQS/print_iqs.php` ที่คงรูปแบบและหัวตาราง "拉力测试 / การทดสอบแรงดึง" ตามเอกสารมาตรฐานโรงงาน พร้อมช่องลงนามครบ 3 ฝ่าย
  6. บันทึก Schema ลง `db_changes.md` และเพิ่มเมนู IQS เข้าสู่แถบข้าง `page/components/php/nav_dropdown.php`
