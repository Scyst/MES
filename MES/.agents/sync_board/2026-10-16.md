- **เวลาทำงาน (Time)**: 08:20 - 08:45 (16/10/26)
- **ปัญหา / สิ่งที่ต้องทำ (Why)**:
  1. **ปัญหายอด Stock เบิ้ลเมื่อย้ายพาเลท (Stock Inflation)**: เมื่อตรวจนับ Cycle Count แล้วพบพาเลทหลงข้าม Location (เช่น เจองานที่ Loc B แต่ระบบเคยลงไว้ที่ Loc A) หากกดยืนยันตรวจนับที่ Loc B แล้ว ยอดในคลังกลับเพิ่มขึ้น ทั้งที่เป็นแค่การย้ายของ สาเหตุเพราะระบบเดิมเพิ่มสต็อกที่ Loc B แต่ไม่ได้ตัดสต็อกออกจาก Loc A อัตโนมัติ (ต้องรอให้คนไปอนุมัติติดลบที่ Loc A เอง ซึ่งทำให้ยอดเบิ้ลและเกิดความสับสน)
  2. **ปัญหาพาเลท/แท็กที่ PRD คืนมา สแกนแล้วไม่ขึ้นใน Requisition**: เมื่อฝ่ายผลิต (PRD) นำงานที่เคยเบิกจ่ายออกไปแล้วกลับมาคืนสโตร์ พนักงานนำแท็กเดิมมาสแกนตรวจนับใน Cycle Count ยอด Location อัปเดตจริง แต่ในหน้าระบบเบิกจ่าย (Material Requisition) ไม่ยอมแสดงแท็กนี้ขึ้นมา สาเหตุเพราะแท็กที่เคยถูกเบิกจ่ายมีสถานะเป็น `WIP` แม้จะนับสต็อกผ่าน Cycle Count สถานะก็ยังเป็น `WIP` อยู่ ทำให้ระบบเบิกจ่าย (ที่ค้นหาเฉพาะแท็ก `AVAILABLE`) มองไม่เห็น
  3. **การเข้าถึงหน้าอนุมัติผลนับ (Approval Accessibility)**: หัวหน้างานต้องสลับหน้าไปมาระหว่าง `cycleCount.php` และ `inventoryDashboard.php` เพื่อดูและอนุมัติผลนับ ทำให้ไม่สะดวก

  1. **ระบบโยกย้ายพาเลทข้ามตำแหน่งแบบสองขาอัตโนมัติ (Single-Click Two-Sided Atomic Relocation)**:
     - ปรับปรุง Stored Procedure `dbo.sp_Store_ApproveCycleCount`: เมื่ออนุมัติแท็กที่ตรวจพบใน Location ใหม่ (`@tag_current_loc != @location_id`) ระบบจะทำการตัดสต็อกออกจาก Location เดิม (`RELOC_OUT`) และเพิ่มสต็อกเข้า Location ใหม่ (`RELOC_IN`) ใน Transaction เดียวกันแบบ Real-time ผลรวมสต็อกสุทธิทั่วทั้งคลังเป็น 0 เท่าเดิม ไม่มียอดบวม

     - เคลียร์/Auto-approve รายการนับที่ค้างอยู่ที่ Location เดิมให้เป็น `AUTO_RELOCATED` ทันที ไม่ต้องตามไปกดอนุมัติติดลบซ้ำ
  2. **ระบบรับของคืนจากฝ่ายผลิต (Dedicated PRD Material Return Flow)**:
