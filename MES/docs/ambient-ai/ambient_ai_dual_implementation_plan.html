DUAL-TRACK IMPLEMENTATION PLAN · SNC MES (FACTORY) + HOME SANDBOX

แผนปฏิบัติการ Ambient AI 2 แทร็กคู่ขนาน: ทดลองระบบที่บ้านในสุดสัปดาห์ แล้วต่อยอดสู่โรงงาน MES ใน 12 สัปดาห์

พิมพ์เขียวลงมือทำจริงสำหรับสร้าง AI สแตนด์บาย 24 ชั่วโมงที่ทำงานจากเหตุการณ์ (Event-Driven) โดยเชื่อมเข้ากับเครื่องมือจริงที่มีอยู่แล้วใน MES/Toolbox (morningBriefTools.php 9 Tools, queryProactiveRedFlags(), Node-RED / MQTT) ควบคู่กับสายส่วนตัวที่ใช้ n8n บน Docker เป็นสนามซ้อมก่อนนำขึ้นระบบโรงงาน

9 Tools พร้อมใช้

ฝั่งโรงงานมี 8 Read-Only SQL Tools + Web Search และ queryProactiveRedFlags() ใน morningBriefTools.php อยู่แล้ว

50–300 บ./ด.

งบเริ่มต้นที่บ้านและโรงงานระยะแรก เมื่อใช้ Pre-Filter กรองสัญญาณด้วยโค้ดก่อนปลุก LLM (ประหยัด Token 80–90%)

12 สัปดาห์ / 4 เฟส

ไต่ระดับความเสี่ยงจาก Home Sandbox (W1–2) → Factory Read-Only Watcher (W3–6) → HITL Agent Inbox (W7–10)

คำตอบสั้นที่สุด: อย่าเพิ่งสร้างระบบที่เขียนฐานข้อมูลโรงงานเองตั้งแต่วันแรก ให้เริ่มจากสายบ้าน (Track B) ด้วย Docker + n8n เพื่อฝึกคุม Pre-Filter, Cooldown และปุ่มอนุมัติ HITL บน Telegram ภายใน 2 สัปดาห์ จากนั้นจึงนำ Pattern เดียวกันมาสวมทับสายโรงงาน (Track A) โดยปลุกฟังก์ชัน Red-Flags และ Tools ที่มีอยู่เดิมใน Toolbox ให้กลายเป็นตัวเฝ้าระวังกะกลางคืนแบบ Read-Only ก่อนเปิดกล่องอนุมัติ Agent Inbox

ทำไมต้องเดิน 2 สายคู่ขนาน: บ้านเป็นสนามซ้อม โรงงานเน้นความเสถียร

การพัฒนา Ambient AI ที่ทำงานเอง 24 ชั่วโมงมีจุดอ่อนสำคัญคือ "พฤติกรรมตอนเกิด Error ตอนไม่มีคนดู" เช่น ลูปเรียก API ไม่หยุด แจ้งเตือนสแปม หรือข้อความภายนอกหลอกให้ AI ทำผิดคำสั่ง (Indirect Prompt Injection) หากนำไปทดลองกับระบบสายการผลิตโรงงานโดยตรง ความผิดพลาดเพียงครั้งเดียวอาจรบกวนหัวหน้างานจนหมดความเชื่อถือ (Alert Fatigue)

แผนนี้จึงออกแบบให้ Track B (ที่บ้าน) ทำหน้าที่เป็น Low-Risk Sandbox สำหรับทดสอบรูปแบบ Prompt, Circuit Breaker และกลไกปุ่มอนุมัติ Human-in-the-Loop ส่วน Track A (โรงงาน B9) จะรับเฉพาะสถาปัตยกรรมที่พิสูจน์แล้วมาเชื่อมต่อกับ PHP 8.2, SQL Server และ Node-RED / MQTT ในวงแลนปิด 10.1.x.x

Track A — แผนต่อยอดระบบโรงงาน MES (SNC B9 / Toolbox OS)

จากการสำรวจโค้ดจริงใน MES/Toolbox/public/api/ai/morningBriefAi.php และ morningBriefTools.php ระบบมีฟังก์ชัน Read-Only 9 ตัว (รายงานผลผลิต, GP/EBITDA, ซ่อมบำรุง PE, System Logs, เงินจมคลังสินค้า, WSM Team Planner, QMS Claims, ค้นหาเว็บ) และฟังก์ชัน queryProactiveRedFlags() อยู่แล้ว จึงสามารถอัปเกรดเป็น 4 Ambient Watchers ได้โดยไม่ต้องรื้อฐานข้อมูลเดิม

dbo.AI_PROCESSED_EVENTS

ตารางเก็บ event_id, dedup_hash และ cooldown_until เพื่อกัน Cron รอบใหม่หรือ Webhook ยิงเบิ้ลมาปลุก AI ซ้ำเรื่องเดิม

dbo.AI_AMBIENT_JOBS

เก็บสถานะงาน (waiting_human, approved, completed, halted), proposed_action_json, tokens_in/out และผู้กดอนุมัติ (RBAC Audit)

dbo.AI_CIRCUIT_BREAKER_CONFIG

กำหนดเพดาน max_retries <= 5, max_tool_rounds <= 4, งบ Token รายวัน และปุ่ม Kill Switch ปิด Agent รายตัวทันที

Track B — แผนสร้างระบบส่วนตัวที่บ้าน (n8n Sandbox & Digital Secretary)

ฝั่งที่บ้านเน้นติดตั้งเร็ว ดูแลง่าย และเป็นเจ้าของข้อมูล 100% โดยใช้ Self-Hosted n8n บน Docker (รันบนคอมพิวเตอร์เดิมหรือ Mini PC งบ 6,000–12,000 บ.) เชื่อมต่อกับ Telegram Bot ที่รองรับปุ่มกด Inline Keyboard สำหรับ Pause-and-Resume ได้ทันที

แผนปฏิบัติการ 12 สัปดาห์ (Phased Rollout Roadmap)

แบ่งเป็น 4 ระยะที่วัดผลได้ชัดเจนทุก 2–4 สัปดาห์ ไม่ลงแรงสร้างระบบใหญ่ทีเดียวจนควบคุมไม่ได้ และมีจุดตัดสินใจเรื่องฮาร์ดแวร์ (Local LLM) ในสัปดาห์ที่ 11–12

เกณฑ์ความปลอดภัยบังคับก่อนเปิดใช้งานจริง (OWASP & Circuit Breaker Gate)

ทุก Workflow ทั้งฝั่งโรงงานและที่บ้านต้องผ่านการตรวจรับความปลอดภัย 5 ข้อนี้ก่อนเปิดรันแบบอัตโนมัติ ตามแนวทาง OWASP Top 10 for LLM Applications และกฎประจำโปรเจ็ค owasp-ai-security.md

ป้องกัน Prompt Injection (OWASP LLM01)

ข้อมูลจากภายนอกหรือข้อความที่ผู้ใช้กรอก (เช่น เนื้อหาอีเมลส่วนตัว, คำอธิบายอาการเสียจากหน้างาน, Webhook ภายนอก) ต้องถูกครอบด้วยแท็ก <untrusted_data>...</untrusted_data> และห้ามนำผลลัพธ์จาก LLM ไปต่อสตริงใน SQL หรือ Shell Command โดยตรง

จำกัดขอบเขตสิทธิ์ (OWASP LLM06 Excessive Agency)

ห้ามมอบบัญชี Admin Database หรือสิทธิ์ DELETE / DROP ให้ Agent เด็ดขาด ชั้น Reasoning ต้องเห็นเฉพาะ Read-Only Tools ส่วนการเขียนลง Production ต้องถูกแยกออกไปอยู่หลังปุ่มอนุมัติ HITL ที่มี RBAC และ CSRF Protection

1. Idempotency & Lock

บันทึก event_id และ dedup_hash ทุกครั้ง กันปัญหา Cron รอบใหม่วิ่งชนรอบเก่าหรือแจ้งเตือนซ้ำซ้อน

2. Circuit Breaker

จำกัด max_retries <= 5, max_tool_rounds <= 4 และเพดาน Token รายวัน ชนเพดานเมื่อไรตัดสวิตช์ทันที

3. Heartbeat & Audit Log

บันทึก job_id, trigger_source, tokens_used, status ทุกครั้ง เพื่อไม่ให้ระบบพังเงียบๆ โดยไม่มีใครรู้

ก้าวแรกที่ลงมือทำได้ทันทีในสุดสัปดาห์นี้

เพื่อไม่ให้แผนนี้ค้างอยู่แค่บนกระดาษ นี่คือ 3 ขั้นตอนแรกที่เริ่มลงมือได้ทันทีโดยไม่กระทบระบบ Production ของโรงงาน

  1. ตั้งสนามซ้อมที่บ้าน (Track B · เสาร์-อาทิตย์นี้): รัน Docker Compose สำหรับ n8n Self-Hosted บนคอมพิวเตอร์ส่วนตัว เชื่อม Telegram Bot แล้วสร้าง Workflow H1 (สรุปนัดหมาย + อีเมลคัดกรองตอน 07:30 น.) เพื่อจับจังหวะการเขียน Pre-Filter และดูค่า Token จริง
  2. ทดลองระบบ Pause-and-Resume (Track B · สัปดาห์ที่ 2): เพิ่มปุ่มอนุมัติใน Telegram ด้วย n8n Wait Node สำหรับร่างตอบอีเมล (H2) และทดสอบส่งข้อความจำลองที่มี Prompt Injection เข้ามาเพื่อเช็คว่า Tagging และ Read-Only Sandbox เอาอยู่จริง
  3. เปิดประตูสู่โรงงานด้วย Read-Only Watcher (Track A · สัปดาห์ที่ 3): ระบุตาราง 3 ตัวลงใน db_changes.md แล้วนำ queryProactiveRedFlags() กับ Tools ใน morningBriefTools.php มาผูกกับ Cron 07:30 น. เพื่อส่งรายงานเตรียมพร้อมก่อนประชุมเช้าแบบ Read-Only 100%

ระบบ Ambient AI ที่สร้างคุณค่าได้จริงไม่ใช่งานที่ซับซ้อนที่สุด แต่คือระบบที่กรองเรื่องปกติทิ้งด้วยโค้ดธรรมดา แล้วปลุก AI มาช่วยคิดเฉพาะตอนที่มนุษย์ต้องตัดสินใจ
